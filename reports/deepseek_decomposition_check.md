# DeepSeek 问题拆分接入检查

检查日期：2026-09-08

## 已验证

- 已按 DeepSeek 官方 OpenAI 兼容接口接入 `/chat/completions`，默认模型为 `deepseek-v4-flash`。
- 仅将用户问题和允许识别的产品名发送给 API，不发送知识库正文或检索结果。
- 无权限用户在 API 调用前被拦截。
- 简单问题不调用 API；复杂问题最多拆成 5 个子问题。
- 已校验 JSON 结构、子问题数量、长度、原问题中的产品标识和版本号；输出异常时回退到原问题。
- 原问题始终保留并参与检索；每个有效子问题预留一个证据位，再使用 RRF 结果补齐 Top 5。
- 拆分后的问题会补充“测试方法、合格判据、封面表字段、简要技术性能”等文档结构词，但不补充具体答案值。
- 10 个本地单元测试通过。
- 未配置 API Key 时，15 道题完整运行成功，`deepseek_success_count=0`，没有把回退结果误记为 DeepSeek 实测。
- 权限隔离题通过；回退状态下结果与原混合检索基线一致：Top 5 为 11/15。
- 已完成真实 DeepSeek 全量评测：8 次 API 请求全部成功，其中 6 道题实际拆分。
- 最终 Top 5 严格通过 15/15，来源覆盖率和定位覆盖率均为 100%，MRR 为 0.9643。
- DeepSeek 问题判断与拆分平均耗时 3895.64 ms，P95 为 4219.39 ms。
- Q008、Q009、Q011、Q013 均通过；权限隔离题继续通过。

## 关键结论

- 单独增加 AI 拆分并不会自动提高准确率；还要让子问题继承“验收合格条件”等原始范围。
- 对“封面版本、看门狗测试、RS422 能力、尺寸缺失”等问题补充不含答案值的文档结构词后，定位能力明显改善。
- 当前结果说明方案值得继续，但 15 道种子题规模较小，且规则已经针对失败模式迭代，不能视为真实业务泛化能力。

## 仍待验证

- 使用新增且冻结的真实问题集进行盲测，避免只适配当前 15 道题。
- 相同配置重复运行的稳定性。
- API token 使用量与单次成本；当前代码尚未汇总 usage 字段。
- DeepSeek 最终回答、引用正确性和证据不足拒答能力。
